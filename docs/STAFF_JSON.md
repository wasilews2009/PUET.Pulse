# PUET.Pulse: як скласти staff.json

`staff.json` — список працівників для месенджера. Поки кадрову систему не
підключено, ви складаєте його вручну й завантажуєте командою `sync:send`
(«Встановлення на один сервер», крок 12). Месенджер перевіряє файл так само,
як дані від справжньої кадрової системи. Після завантаження він сам додає людей
у канали кафедр, інститутів, підрозділів і ректорату.

## 1. Як виглядає файл

Файл має один розділ `records`, у ньому записи працівників, до 1000 за раз:

```json
{ "records": [
  { "hrId": "HR-0001", "corporateId": "PUET-0001", "email": "i.petrenko@puet.edu.ua",
    "fullNameUk": "Іван Петренко", "position": "Інженер Інформаційного центру",
    "orgUnitCodes": ["IT_CENTER"] }
] }
```

Правила запису:

- лапки лише прямі `"`, не «ялинки» і не `“ ”`;
- після останнього запису й останнього поля коми немає;
- коди (`IT_CENTER`, `RECTORATE` тощо) пишуться латиницею, великими літерами,
  точно як у таблицях нижче;
- файл зберігайте в кодуванні UTF-8 (у Блокноті Windows: «Зберегти як» →
  «Кодування: UTF-8»).

Перевірити, що файл коректний JSON, можна на сервері:
`python3 -m json.tool /home/ubuntu/staff.json > /dev/null && echo OK`.

## 2. Поля запису

| Поле | Обов'язкове | Формат | Де взяти значення |
|---|---|---|---|
| `hrId` | так | рядок до 64 символів | Табельний номер у кадровій системі (відділ кадрів). Ключ запису: за ним месенджер оновлює людину при повторному завантаженні. Не змінюйте його. |
| `corporateId` | так | рядок до 64 символів | Службовий ID людини (номер посвідчення або логін в університеті). Його бачать у профілі, а `admin:bootstrap` шукає людину саме за ним. |
| `email` | так | адреса пошти | Корпоративна пошта. **Має точно збігатися з поштою облікового запису в Keycloak / AD**: за нею месенджер впізнає людину при першому вході. |
| `fullNameUk` | так | до 256 символів | Прізвище, ім'я (і за бажанням по батькові) українською, як у наказі про прийняття. |
| `fullNameEn` | ні | до 256 символів | Ім'я латиницею, як у закордонному паспорті або на сайті університету. Показується в англійському інтерфейсі. |
| `position` | так | до 256 символів | Посада зі штатного розпису: «Ректор», «Доцент», «Керівник ННЦ «STEAM-ХАБ»». |
| `status` | ні | `ACTIVE`, `ON_LEAVE`, `DISMISSED` | За замовчуванням `ACTIVE`. `ON_LEAVE` (відпустка по догляду, тривала відсутність) тимчасово закриває доступ. `DISMISSED` звільняє: доступ закривається назавжди, архів зберігається. |
| `phone` | ні | `+380 50 123 45 67` | Службовий або особистий телефон. Його бачать лише сама людина і відділ кадрів. |
| `birthDate` | ні | `РРРР-ММ-ДД` | Дата народження. Для працівників не обов'язкова. |
| `locale` | ні | `uk` або `en` | Мова інтерфейсу за замовчуванням. Без поля: українська. |
| `academicDegree` | ні | текст | Науковий ступінь: «кандидат економічних наук», «доктор філософії». |
| `academicTitle` | ні | текст | Вчене звання: «доцент», «професор». |
| `primaryDepartmentCode` | ні | код кафедри | Основна кафедра викладача (таблиця 4). |
| `departmentCodes` | ні | список кодів кафедр | Усі кафедри, де людина працює, разом з основною. Людина потрапляє в канал кожної з них. |
| `orgUnitCodes` | ні | список кодів підрозділів | Підрозділи, де людина працює (таблиця 5). Людина стає учасником каналу кожного з них. |
| `roles` | ні | список ролей | Ролі з областю дії (розділ 3). Без ролей людина — звичайний працівник: пише в чати, отримує документи, бачить «Сервіси». |

## 3. Ролі

Кожна роль у `roles` — об'єкт із назвою ролі й областю, де вона діє:

```json
"roles": [{ "role": "DEPARTMENT_HEAD", "departmentCode": "MARKETING" }]
```

Поля області: `instituteCode` (таблиця 3), `departmentCode` (таблиця 4),
`orgUnitCode` (таблиця 5), `dormitoryNumber` (число 1–4). Людина з роллю,
прив'язаною до підрозділу (`orgUnitCode`), стає модератором його каналу: публікує
оголошення, починає дзвінки, запускає опитування.

| Роль | Для кого | Область | Другий фактор (TOTP) |
|---|---|---|---|
| `LECTURER` | викладачі (НПП), тренери STEAM-ХАБу та «Інтерлінгви» | `departmentCode` або `orgUnitCode` | ні |
| `DEPARTMENT_HEAD` | завідувачі кафедр | `departmentCode` (обов'язково) | ні |
| `INSTITUTE_DIRECTOR` | директори ННІ, коледжів, ліцею | `instituteCode` | так |
| `ADMIN_STAFF` | канцелярія, кадри, фінанси, юристи, приймальна комісія, якість, Інформаційний центр | `orgUnitCode` | так |
| `TRUST_SERVICE_OFFICER` | омбудсмен, психологічна служба, військовий облік | `orgUnitCode` | так |
| `CIVIL_PROTECTION_OFFICER` | підрозділ цивільного захисту: тривоги | `orgUnitCode: "CIVIL_PROTECTION"` | ні |
| `FACILITIES_STAFF` | АГР: будівлі, теплоенергетика, транспорт | `orgUnitCode` (`AHR` або його відділ) | ні |
| `DORM_COMMANDANT` | коменданти гуртожитків | `dormitoryNumber` (обов'язково) | ні |

Ролі **`RECTORATE`** і **`SUPER_ADMIN`** у `staff.json` вказати не можна, так
задумано для безпеки. Їх призначає адміністратор в «Адмініструванні» → «Ролі»
(розділ 6).

## 6. Ректорат

Члени ректорату (ректор, перший проректор, проректори, вчений секретар)
додаються у два кроки.

**Крок 1. Запис у `staff.json`** з підрозділом `RECTORATE`. Якщо людина входить
до Вченої ради, додайте ще `ACADEMIC_COUNCIL`:

```json
{ "hrId": "HR-0100", "corporateId": "PUET-0100", "email": "rector@puet.edu.ua",
  "fullNameUk": "Прізвище Ім'я По батькові", "fullNameEn": "Name Surname",
  "position": "Ректор", "academicDegree": "доктор економічних наук", "academicTitle": "професор",
  "orgUnitCodes": ["RECTORATE", "ACADEMIC_COUNCIL"] },
{ "hrId": "HR-0101", "corporateId": "PUET-0101", "email": "prorector.edu@puet.edu.ua",
  "fullNameUk": "Прізвище Ім'я По батькові", "position": "Проректор з науково-педагогічної роботи",
  "orgUnitCodes": ["RECTORATE", "ACADEMIC_COUNCIL"] },
{ "hrId": "HR-0102", "corporateId": "PUET-0102", "email": "secretary@puet.edu.ua",
  "fullNameUk": "Прізвище Ім'я По батькові", "position": "Вчений секретар",
  "orgUnitCodes": ["RECTORATE", "ACADEMIC_COUNCIL"] }
```

Проректор, який одночасно викладає, отримує ще кафедру й роль викладача:
`"departmentCodes": ["MANAGEMENT"], "roles": [{ "role": "LECTURER", "departmentCode": "MANAGEMENT" }]`.

**Крок 2. Роль «Ректорат» в адмін-панелі.** Після завантаження файлу
адміністратор відкриває «Адміністрування» → «Ролі» → «Призначити роль»:

1. у полі пошуку знайдіть людину за прізвищем і виберіть її;
2. «Роль»: `RECTORATE` (поля «Область» для цієї ролі немає, роль діє на весь університет);
3. «Діє до» залиште порожнім;
4. натисніть «Призначити роль».

Роль дає керівний рівень доступу і робить людину власником закритого каналу
«Ректорат». Вхід із цією роллю вимагає TOTP, тому в Keycloak цій людині
додайте Required user actions → **Configure OTP** («Встановлення на один
сервер», крок 10). Роль із панелі синхронізація не змінює і не знімає. Якщо
людина залишає посаду, відкличте роль там же кнопкою «Відкликати».

## 7. Керівник STEAM-ХАБу

Підрозділ ННЦ «STEAM-ХАБ» уже є, код `STEAM_HUB`. Керівник — учасник підрозділу
з роллю, прив'язаною до нього. Тоді він стає модератором каналу STEAM-ХАБу:
публікує оголошення, починає дзвінки, проводить опитування й консультації.

```json
{ "hrId": "HR-0200", "corporateId": "PUET-0200", "email": "steam.head@puet.edu.ua",
  "fullNameUk": "Прізвище Ім'я", "position": "Керівник ННЦ «STEAM-ХАБ»",
  "orgUnitCodes": ["STEAM_HUB"],
  "roles": [{ "role": "LECTURER", "orgUnitCode": "STEAM_HUB" }] }
```

Тренери STEAM-ХАБу записуються так само: `orgUnitCodes: ["STEAM_HUB"]` і роль
`LECTURER` з `"orgUnitCode": "STEAM_HUB"`. Співробітник без ролі
(`"orgUnitCodes": ["STEAM_HUB"]` без `roles`) — звичайний учасник каналу. Якщо
керівник ще й викладає на кафедрі, додайте другу роль:
`{ "role": "LECTURER", "departmentCode": "COMPUTER_SCIENCE_IT" }`.

## 9. Завантаження і зміни

Файл складіть на своєму комп'ютері й перешліть на сервер. Команди виконуйте
по одній. У PowerShell на Windows:

```bash
scp C:\Users\<ваше ім'я>\Documents\staff.json ubuntu@<IP сервера>:/home/ubuntu/staff.json
```

Потім на сервері (`ssh ubuntu@<IP сервера>`):

```bash
cd /srv/puet-pulse/app
```

```bash
E="sudo PULSE_ENV_FILE=/etc/puet/pulse.env"
```

```bash
python3 -m json.tool /home/ubuntu/staff.json > /dev/null && echo OK
```

```bash
$E pnpm sync:send hr/staff /home/ubuntu/staff.json
```

Відповідь `HTTP 200` з `"errors":[]` означає, що всі записи прийнято. Якщо
запис має помилку, у відповіді буде його номер (з нуля) і поле, наприклад
`unknown orgUnitCode` — код підрозділу написано з помилкою.

Що відбувається при повторному завантаженні:

- людина з тим самим `hrId` оновлюється: ім'я, посада, підрозділи, кафедри,
  ролі з файлу;
- ролі з файлу замінюють попередні ролі з файлу; ролі, призначені в
  адмін-панелі (`RECTORATE`, `SUPER_ADMIN` та інші), лишаються;
- людей, яких немає у новому файлі, месенджер не видаляє. Щоб закрити доступ,
  поставте їм `"status": "DISMISSED"` або надішліть файл звільнень (крок 12);
- канали оновлюються автоматично одразу після завантаження.

Після перевірки видаліть копію з персональними даними з домашньої теки
сервера: `rm /home/ubuntu/staff.json`. Оригінал зберігайте у відділі кадрів.
Кожна нова людина має також мати обліковий запис у Keycloak з тією самою
поштою («Встановлення на один сервер», крок 10).
